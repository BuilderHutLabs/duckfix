# WDuck MVP (etapy 0–1) — plan implementacji

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PWA, która otwiera PDF lub zdjęcia, automatycznie obraca strony do pionu i prostuje przekrzywienie, pokazuje siatkę do szybkiej korekty (obrót, kolejność, usuwanie, wstawianie) i eksportuje gotowy PDF. Wdrożona na `https://builderhutlabs.github.io/wduck/`.

**Architecture:** Czysty model dokumentu (lista stron z obrotem, kątem prostowania i flagami, niedestrukcyjny do eksportu) plus potok analizy: render przez pdf.js, potem detektor orientacji (Tesseract OSD w Web Workerach, za wymiennym interfejsem), potem estymacja skosu w czystym JS. Eksport przez pdf-lib: obrót bezstratnie przez `/Rotate`, strony prostowane rasteryzowane ponownie. UI w React, cała logika poza komponentami.

**Tech Stack:** Node 24, Vite + React 18 + TypeScript, `pdfjs-dist@4`, `pdf-lib@1.17.1`, `tesseract.js@5` (legacy core dla OSD), `@dnd-kit/core` + `@dnd-kit/sortable`, `idb-keyval`, `vite-plugin-pwa`, Vitest + @testing-library/react.

**Spec:** `docs/superpowers/specs/2026-11-18-pdf-app-design.md`

**Poza zakresem tego planu** (osobne plany później, etapy 2–5 ze spec §7): adnotacje, podpis, konwersja PDF do zdjęć, łączenie i dzielenie, puste strony, kompresja, warstwa OCR, numeracja, znak wodny, Capacitor i Sklep Play.

## Global Constraints

- Vite `base: '/wduck/'`; manifest `scope` i `start_url` = `/wduck/`. Nazwa wyświetlana: `WDuck`.
- Zero żądań sieciowych z treścią dokumentów, brak analityki. Pliki Tesseracta (worker, core WASM, `osd.traineddata`, `pol.traineddata`, `eng.traineddata`) serwowane z `/wduck/tesseract/` i `/wduck/tessdata/`, nie z CDN.
- Żadne prawdziwe skany nie trafiają do repo: `samples/` w `.gitignore`.
- Interfejs po polsku, wszystkie teksty w `src/ui/strings.ts`.
- Operacje niedestrukcyjne do eksportu, każda zmiana dokumentu przez historię (cofnij/ponów).
- Puste/niepewne strony tylko oznaczane, nic nie jest usuwane bez akcji użytkownika.
- Prostowanie tylko gdy |kąt| > 0.3°, zakres wykrywania ±10°, rozdzielczość ~0.1°. Strony z warstwą tekstową (nie skan) nie są prostowane.
- Rasteryzacja prostowanej strony: 300 DPI (decyzja: przybliżenie „rozdzielczość źródła, maks. 300”). Strona prawie dwutonowa → PNG w skali szarości, inaczej JPEG jakość 0.9.
- Analiza: render do dłuższego boku 1400 px (do strojenia w kroku 0), pula 2 workerów.
- Cel spec: ≥95% stron poprawnych bez dotykania, ≤3 min / 100 stron na iPadzie znajomej.

## Review Focus

1. **PDF zaszyfrowany lub uszkodzony:** komunikat po polsku, powrót do ekranu startowego, bez crasha (test w Task 5).
2. **Strona źródłowa ma już `/Rotate`:** nowy obrót dodaje się do istniejącego, a nie go nadpisuje (testy w Task 2 i Task 7).
3. **Strona naprawdę pozioma** (np. szeroka tabela na stronie A4 landscape): orientacja liczona z tekstu, nie z proporcji, a eksport zachowuje wymiary strony (test w Task 7).
4. **Duży plik na iOS:** strony przetwarzane po kolei, canvasy zwalniane (`width = height = 0`), żeby Safari nie zabił karty (test pamięci kolejki w Task 6, ręczny w Task 11).
5. **Karta zamknięta w trakcie:** po ponownym otwarciu sesja (pliki i stan) wraca i analiza dokańcza brakujące strony (test w Task 9).
