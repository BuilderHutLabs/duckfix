# DuckFix V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn DuckFix into a 4-language document scanner (camera + auto-crop, searchable PDF, compression, merging, blank-page removal), testable at a separate link `builderhutlabs.github.io/duckfix-v2/` without touching the live app.

**Architecture:** One codebase. A build-time namespace (env vars) switches base path, app name and storage keys for the test deployment. Strings become per-language dictionaries behind the same `strings` import. New features feed the existing pipeline: camera scans become ordinary image sources, OCR and compression are export options, and blank pages are a new analysis flag.

**Tech Stack:** Vite 8, React 18, TypeScript, Vitest (jsdom), pdf.js 4, pdf-lib 1.17, tesseract.js 5, vite-plugin-pwa, idb-keyval.

**Spec:** `docs/superpowers/specs/2026-11-20-duckfix-v2-design.md`

## Global Constraints

- Work on local branch `v2` (from `main` at d4ad9c4). Never push `main` and never deploy `/duckfix/` without the user's explicit approval.
- Default build (no env vars) must behave exactly like today:
  - base `/duckfix/`;
  - keys `wduck` (IndexedDB), `wduck.deskew`, `wduck-theme`, `duckfix-palette`.
- With `VITE_STORAGE_NS=duckfix-v2`:
  - every localStorage key and the IndexedDB database name differ from the default build;
  - base is `/duckfix-v2/`;
  - manifest name is `DuckFix V2`.
- No OpenCV and no new dependency over ~100 kB gzipped.
- Languages `pl`, `en`, `de`, `es`. Fallback is `en`. Each language implements its own plural rules.
- Export file suffixes: pl ` (poprawiony)`, en ` (fixed)`, de ` (korrigiert)`, es ` (corregido)`.
- Traineddata `pol` and `eng` stay precached (offline). `deu` and `spa` are fetched by `scripts/fetch-tesseract.mjs` but excluded from precache and runtime-cached on first use.
- The app never deletes pages on its own. "Usuń puste strony" is a user tap and undoable.
- Tap targets are at least 44 px. Everything works in light and dark and in all 4 colour sets.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Delete `public/_test-mixed.pdf` before any build or commit. Never commit real scans.
- `npm test`, `npx tsc --noEmit` and `npm run build` pass at the end of every task.

## Review Focus

1. **iPad photo: HEIC and EXIF orientation.** A portrait iPhone/iPad photo must reach the crop screen upright and export upright. Decode with `createImageBitmap(blob, { imageOrientation: 'from-image' })` (Task 6 test with an EXIF-rotated JPEG fixture or a decode-mock assertion).
2. **12 MP photos on iPad memory.** The crop screen and warp must downscale (detection ≤ 400 px, warp output long side ≤ 2400 px, never a canvas over `MAX_CANVAS_PIXELS`) (Task 6 test: warp output size cap).
3. **v2 on the same origin.** The inline script in `index.html` must read the namespaced theme and palette keys too. Otherwise v2 starts with v1's theme (Task 1 test on the transformed html).
4. **OCR on pages that already have text.** A PDF page with a text layer and no raster change must not get a second, duplicate text layer (Task 4 test).
5. **Language switch while a notice is shown or during export.** Notices built from `strings` at creation time may stay in the old language. This is acceptable, but nothing may crash and the next notice uses the new language (Task 2 test: switch language, trigger an error, assert new-language text).
